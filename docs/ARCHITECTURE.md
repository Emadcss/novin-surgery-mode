# معماری

## نمای کلی

```
 ┌────────────── کیوسک (Tauri 2) ──────────────┐        ┌──────────── سرور ────────────┐
 │  WebView: Vue 3 SPA (کیوسک + پنل مدیریت)    │  HTTP  │  FastAPI  ──►  PostgreSQL 16 │
 │  Rust: get_kiosk_config · print_receipt     │ ─────► │  /api/*   /media/* (عکس‌ها)   │
 └──────────┬──────────────────────────────────┘        └──────────────────────────────┘
            │ ESC/POS raster (TCP:9100 / دستگاه)
        چاپگر حرارتی ۸۰mm
```

- کیوسک و پنل مدیریت **یک اپ Vue** هستند (مسیرهای `/` و `/admin/*`، حالت hash).
- اپ هم داخل Tauri و هم در مرورگر معمولی (گوشی/دسکتاپ) اجرا می‌شود؛ در مرورگر چاپ با `window.print()` انجام می‌شود.
- همه‌ی منطق کسب‌وکار (اعتبارسنجی، صدور کد، شماره نوبت) در **سرور** است؛ فرانت فقط نمایش و ورودی است.

## بک‌اند (`backend/`)

| فایل | نقش |

| `app/schemas.py` | مدل‌های Pydantic ورودی/خروجی (منبع قرارداد API) |

| `app/deps.py` | وابستگی‌ها: session، `kiosk_guard`، `current_admin` |
| `app/routers/` | `kiosk`, `auth`, `doctors`, `appointments`, `patients`, `stats`, `admins`, `app_settings` |

### مدل داده

- **Doctor** — `no` (شماره‌ی یکتا و **هرگز مصرف‌مجدد** برای کد پذیرش)، `category` (`eye`/`cos`)، `does_injection` (فقط برای چشم؛ پیش‌فرض روشن)، `is_active`، `is_deleted` (حذف نرم)، `photo_path`.
- **Appointment** — `code` (۱۱ رقم)، `seq` (شماره‌ی نوبت روز)، `visit_date`، `procedure`، `category`، `doctor_id` + `doctor_name` (نام در لحظه‌ی ثبت کپی می‌شود)، `first_name`، `last_name`، `mobile`، `has_history`، `status` (`booked` / `done` / `cancelled`). قید یکتایی `(visit_date, seq)`.
- **Admin** — `name` و `pin_hash` (bcrypt).
- **Setting** — جفت کلید/مقدار؛ فعلاً فقط `theme`.
- بیمار موجودیت جدا ندارد؛ با شماره‌ی موبایل از روی نوبت‌ها تجمیع می‌شود.

### کد پذیرش (۱۱ رقم)

```
 1  02  0807  1  004
 │  │   │     │  └─ شماره‌ی نوبت همان روز (۳ رقم، بر اساس تاریخ تهران)
 │  │   │     └──── سابقه‌ی جراحی در مرکز: ۰ یا ۱
 │  │   └────────── ماه و روز شمسی (MMDD)
 │  └────────────── شماره‌ی پزشک (۲ رقم)
 └───────────────── گروه: ۱ = چشم، ۲ = زیبایی
```

سرور کد را می‌سازد؛ فرانت هرگز کد تولید نمی‌کند. شماره‌ی نوبت با قید یکتایی دیتابیس در برابر ثبت همزمان محافظت می‌شود.

### روند عمل و پزشک

| عمل | دسته | پزشکان قابل انتخاب |
|---|---|---|
| `inj_eye` (تزریق چشمی) | چشم | پزشک چشم با `does_injection=true` |
| `surg_eye` (جراحی چشمی) | چشم | همه‌ی پزشکان چشم |
| `cos` (زیبایی) | زیبایی | پزشکان زیبایی |

فقط پزشک فعال و حذف‌نشده نمایش داده می‌شود. اگر بین انتخاب و تأیید پزشک غیرفعال شود، سرور `409` می‌دهد و کیوسک بیمار را به انتخاب پزشک برمی‌گرداند.

### احراز هویت و امنیت

- **کیوسک:** عمومی است؛ اگر `KIOSK_KEY` تنظیم شده باشد، همه‌ی `/api/kiosk/*` باید هدر `X-Kiosk-Key` بفرستند (مقایسه‌ی ثابت‌زمان).
- **ادمین:** ورود فقط با PIN چهار رقمی (bcrypt) ← JWT (HS256، پیش‌فرض ۱۲ ساعت). پس از ۵ تلاش ناموفق از یک IP، ۵ دقیقه قفل می‌شود (در حافظه؛ برای چند پردازه به Redis منتقل شود).
- فایل‌های `/media` فقط عکس پزشکان هستند (مربع‌برش‌شده و فشرده‌شده توسط Pillow).
- داده‌ی شخصی ذخیره‌شده: نام، نام‌خانوادگی، موبایل. **کد ملی ذخیره نمی‌شود.**

### چیدمان و مقیاس

`useShell` از روی ابعاد پنجره یکی از سه چیدمان را برمی‌گزیند (`mobile` اگر عرض ≤ ۶۴۰، وگرنه `landscape` اگر عرض ≥ ارتفاع، وگرنه `portrait`) و `font-size` ریشه را طوری تنظیم می‌کند که **۱rem در ابعاد مرجع = ۱۶px** باشد (افقی ۱۲۸۰×۸۰۰، عمودی ۸۰۰×۱۲۸۰، موبایل ۳۹۰×۸۴۴). همه‌ی اندازه‌ها `rem` هستند؛ پس طراحی روی مانیتورهای بزرگ‌تر (۲۰+ اینچ) متناسب بزرگ می‌شود. وضعیت روی عنصر `.shell` با `data-layout`، `data-screen` و `data-step` ثبت می‌شود و CSS با همین‌ها هر چیدمان را تنظیم می‌کند. هر قاعده‌ی مخصوص یک چیدمان باید با `.shell[data-layout="…"]` محدود شود تا چیدمان‌های دیگر دست‌نخورده بمانند.

### نکات دوسویه‌نویسی (RTL)

- شماره‌ی موبایل با `LRI…PDI` (`⁦…⁩`) ایزوله می‌شود تا «۰۹» همیشه سمت چپ باشد.
- کد پذیرش و ارقام با `unicode-bidi: isolate` و `direction: ltr` نمایش داده می‌شوند.
- ارقام در UI فارسی‌اند؛ ورودی عربی/فارسی در سرور به لاتین نرمال می‌شود.

### متن‌های قابل ویرایش
فهرست و پیش‌فرض متن‌ها در `frontend/src/lib/texts.ts` است؛ store `texts` مقدار ویرایش‌شده را (از `GET /api/kiosk/settings` → `texts`) یا پیش‌فرض را برمی‌گرداند. فقط مقدارهای تغییرکرده در جدول `settings` (کلید `text:<key>`) ذخیره می‌شوند و `{name}` با نام بیمار جایگزین می‌شود. برای افزودن متن تازه فقط یک ردیف به `TEXT_DEFS` اضافه کنید.

### جای پرونده
افقی: پرونده سمت چپ و پنل سمت راست. عمودی: در مرحله‌های انتخاب (نوع جراحی، نوع عمل، پزشک) پرونده پایین؛ از ورود نام به بعد پرونده بالا و کیبورد پایین.

### حالت روشن/تیره

توکن‌های رنگ در `:root` و `[data-theme="dark"]`. مقدار از `GET /api/kiosk/settings` خوانده می‌شود (`light` پیش‌فرض، `dark`، `auto`). حالت تیره فقط وقتی فعال می‌شود که ادمین انتخاب کند؛ `prefers-color-scheme` سیستم‌عامل به‌طور مستقیم اعمال **نمی‌شود** (محیط کلینیک همیشه روشن است).

## پوسته‌ی Tauri (`src-tauri/`)

- پنجره‌ی تمام‌صفحه، بدون قاب، غیرقابل تغییر اندازه.
- `get_kiosk_config` ← `kiosk.config.json` را می‌خواند (کنار فایل اجرایی) و `api_base` و `kiosk_key` را به فرانت می‌دهد؛ **آدرس چاپگر به فرانت داده نمی‌شود**.
- `print_receipt(png_base64)` ← PNG قبض را به bitmap تک‌بیتی تبدیل می‌کند، دستور `GS v 0` + برش کاغذ می‌سازد و می‌فرستد به `tcp:IP:9100` یا فایل/دستگاه (`\\.\USB001`، `\\localhost\Receipt`، `/dev/usb/lp0`).
- قبض در فرانت روی canvas رسم می‌شود (عرض ۵۷۶ پیکسل)، پس فونت فارسی چاپگر مهم نیست.
